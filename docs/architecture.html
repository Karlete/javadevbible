Flujos principales

index.html→fetch search-index.json→≥2 caracteres · debounce 200 ms→trocea en palabras (todas deben aparecer)→puntúa y ordena→top 10 como <a>→página de tema

Pesos: título 10 · categoría 5 · keywords 3 · descripción 2, más bonus por inicio de palabra en el título, frase exacta y prefijo. Plural → singular ("threads" encuentra "Multithreading"). Idéntico en el servidor MCP, con tests. Si el fetch falla, lo dice (con file:// suele fallar: usa python -m http.server).

tools/verify.sh el "compilador" del proyecto

  1. Enlaces internos — todo href local resuelve a un archivo
  2. Índice de búsqueda — URLs del JSON = archivos en topics/
  3. BOM UTF-8 — ningún HTML empieza por EF BB BF
  4. Restos de debug — sin console.* en js/
  5. Clase muerta — sin comparison-table
  6. Meta description — presente y de 70–160 caracteres
  7. Cifras escritas a mano — index, README, CLAUDE.md y mcp/README = disco
  8. Bloques de código — spans equilibrados, sin </tag&gt;, sin etiquetas crudas
  9. Clases CSS — toda clase usada está definida
  10. Marcado prohibido — sin style="" ni cajas ASCII lado a lado
  11. Tarjetas del índice — toda página aparece en su categoría
  12. Cabecera SEO — canonical propio + Open Graph
  13. Sitemap — igual al disco
  14. Inyección por campo — sin @Autowired private fuera de tests y ejemplos ❌

Lo que no comprueba

  • Que algo se vea o funcione bien (hace falta navegador).
  • Anclas #seccion dentro de enlaces.
  • La estructura de la plantilla (Sección 0, Do/Don't, nº de preguntas).
  • El resto de convenciones Java (jakarta, LAZY, records, ProblemDetail, dominio).
  • Que mcp/ compile: para eso, ./mvnw -q test.

Recetas para una nueva feature

Añadir una página de tema

  1. Copiar relationships.html y reescribir el contenido.
  2. Entrada en search-index.json con la etiqueta de categoría de sus hermanas.
  3. <li> en la tarjeta de index.html.
  4. Enlazarla desde Related Topics de alguna hermana.
  5. Actualizar "94" en index (meta, stats, aria-label), README y CLAUDE.md.
  6. verify.sh + navegador.

Añadir JS para todo el sitio

  1. Archivo nuevo en js/, IIFE + 'use strict', salir si no existe su DOM.
  2. Nada de innerHTML con datos, ni console.*, ni dependencias.
  3. No hay includes: el <script> se añade a mano en las 94 páginas (sed revisado).
  4. Estilos en main.css; respetar prefers-reduced-motion.
  5. Probar a 320px, 900/901px y escritorio.

Tocar la búsqueda

  1. El JSON debe seguir plano (verify.sh usa grep).
  2. Cualquier cambio de forma o de pesos se replica en JavaBibleTools.java.
  3. No tocar data-open desde otros scripts.
